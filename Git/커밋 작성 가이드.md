# Git 커밋 메시지 작성 가이드

## 커밋 메시지의 중요성
- 변경 이력을 문서화하여 팀원간의 소통을 원활하게 합니다.
- 메시지를 통해 변경된 내용을 이해하고, 코드의 맥락을 알 수 있습니다.

## 커밋 메시지 구조
- **제목(Subject), 본문(Body), 꼬리말(Footer)**

```java
type: [#issueNumber - ]Subject

Body

Footer
```

## 커밋 메시지 태그
| 태그     | 설명                                       | 예시                 |
|----------|------------------------------------------|--------------------|
| feat     | 새로운 기능을 추가했거나 기존 기능을 변경한 경우              | feat: 회원가입 기능 추가   |
| fix      | 기능에 대한 버그 수정                             | fix: 로그인 오류 수정     |
| build    | 빌드 관련 수정                                 | build: 빌드 스크립트 수정  |
| chore    | 배포, 빌드 등과 같이 프로젝트의 기타 작업들에 대해 추가/수정했을 경우 | chore: .gitignore 수정 |
| docs     | 직접적인 코드 변화 없이 문서(주석)만 수정했을 경우            | docs: README 파일 업데이트 |
| style    | UI를 추가/변경 하거나 스타일 관련 작업을 했을 경우           | style: 코드 포맷팅 개선   |
| refactor | 기능의 변화가 아닌 코드 리팩터링                       | refactor: 변수 이름 변경 |
| test     | 테스트 코드 추가/수정                             | test: 유닛 테스트 추가    |
| release  | 버전 릴리즈                                   | release: v1.0.0 배포 |


## 좋은 커밋 메시지를 위한 7가지 약속
1. 제목과 본문은 한 줄을 띄워 분리한다.
2. 제목은 영문 기준 50자 이내로 작성한다.
3. 제목 첫글자를 대문자로 작성한다.
4. 제목 끝에 . 를 작성하지 않는다.
5. 제목은 명령조로 작성한다.
6. 본문은 영문 기준 72자마다 줄을 바꾼다.
7. 본문은 어떻게보다 무엇을, 왜에 맞춰 작성한다.
