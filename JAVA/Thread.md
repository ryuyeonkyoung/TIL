## 프로세스 vs 스레드
###  프로세스
- 실행중인 프로그램의 인스턴스이다.
- CPU는 빠른 속도를 유지하기 위해 하드디스크가 아닌 메모리에 로딩한다. (CPU > 메모리 > 하드디스크)
- 프로세스는 서로 독립적인 메모리 공간을 사용하므로, 스레드에 비해 문맥교환의 오버헤드가 크다.

###  스레드
- 프로세스 내에서 실행되는 작업의 단위이다.
- CPU를 사용하는 최소단위이다.
- 메모리를 비우지 않고 스택과 레지스터만 교환하면 되므로, 프로세스에 비해 문맥교환의 오버헤드가 작다.

| 특성                    | **프로세스**                                  | **스레드**                                             |
|-------------------------|-------------------------------------------|-----------------------------------------------------|
| **정의**                 | 실행 중인 프로그램의 인스턴스                          | 프로세스 내에서 실행되는 작업의 단위                                |
| **문맥 교환**            | 문맥 교환의 오버헤드가 크다<br/>(프로세스는 독립적인 메모리 공간을 사용하므로) | 문맥 교환의 오버헤드가 작다<br/>(스택과 레지스터만 교환하면 되므로)            |


###  프로세스와 스레드의 관계
- CPU는 Process 안에 있는 스레드를 실행한다.
  -> 하나의 프로세스 안에는 최소 한개의 스레드가 있어야 한다.
- 하나의 프로세스 내에 여러개의 스레드가 있을 수 있다. (멀티태스킹)
- 프로세스는 독립적인 메모리 공간을 할당받지만, 스레드는 같은 메모리를 공유할 수 있다.

## 스레드의 장단점
### 장점
- 멀티태스킹을 통해 사용자에게 동시성을 제공하여 사용자 경험을 개선한다.
- 문맥교환시 오버헤드가 적다.
### 단점
- 공유자원에 동시에 접근할 때 경쟁 상태가 발생한다.
- 이를 해결하기 위해 동기화가 필요하지만, 이로 인해 성능저하나 병목현상이 생길 수 있다.

## 멀티 프로세스 vs 멀티 스레드
### 멀티 프로세스
- 문맥 교환이 느리다.
- 멀티 스레드보다 많은 메모리와 CPU를 차지한다.
- 하나의 프로세스에 문제가 생겨도 다른 프로세스에 영향을 끼치지 않는다.
### 멀티 스레드
- 문맥 교환이 빠르다
- 멀티 프로세스보다 적은 메모리 공간을 차지한다.
- 하나의 스레드에 문제가 생기면 전체 스레드가 영향을 받는다.

| 특성                   | **멀티 프로세스**                                     | **멀티 스레드**                                         |
|------------------------|-------------------------------------------------------|----------------------------------------------------|
| **문맥 교환**      | 느리다 (독립적인 메모리 공간)        | 빠르다 (메모리 공유)                                       |
| **메모리 사용량**       | 많다 (독립적인 메모리 공간)           | 적다 (메모리 공유)                                        |
| **안정성**              | 높다<br/>(각 프로세스는 독립적이므로 다른 프로세스에 영향 없음) | 낮다<br/>(스레드는 메모리를 공유하므로 하나의 스레드에 오류가 나면 전체 프로세스에 영향 미침) |
