# AWS & 네트워크 기초

## TCP
- 데이터 신뢰성, 순서 보장, 흐름/혼잡 제어 등 신뢰성 중심의 연결 지향 프로토콜
- HTTP/HTTPS, DB 연결 등 대부분 TCP 기반

+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

### 장점/단점/실무 포인트
- 장점: 신뢰성, 오류 검사, 재전송, 흐름/혼잡 제어
- 단점: 느림, 대역폭 소모, 근거리/개인망 부적합
- 실무: SYN flood 방어, Keep-Alive, 커널 튜닝 등 필요

## UDP
- 빠른 속도, 오버헤드 적음, 신뢰성/순서 미보장, 실시간성 우수
- 스트리밍, 게임, P2P 등에서 활용

### 구조
```
0      7 8     15 16    23 24    31
+--------+--------+--------+--------+
|     Source      |   Destination   |
|      Port       |      Port       |
+--------+--------+--------+--------+
|                 |                 |
|     Length      |    Checksum     |
+--------+--------+--------+--------+
|
|          data octets ...
+---------------- ...
```

### 장점/단점/실무 포인트
- 장점: 빠름, 일부 패킷 유실 허용, 멀티캐스트 지원
- 단점: 신뢰성/순서 미보장, 패킷 도달 확인 불가
- 실무: 스트리밍, NAT, 패킷 유실 복구 필요시 자체 구현

---

## 시스템 콜/인터럽트/FD/소켓 등
- 시스템 콜: 커널을 통한 안전한 자원 접근 (read, write, open 등)
- 하드웨어 인터럽트: 이벤트 기반 처리로 CPU 효율화
- 파일 디스크립터: 리눅스에서 모든 자원을 파일처럼 관리, FD로 식별
- socket/bind/listen/accept: 네트워크 서버의 기본 동작 흐름
- 멀티 프로세스/병렬 처리: fork, 스레드풀, 논블로킹 IO 등

# AWS 인프라 기초

## AWS의 필요성 및 기본 구성
- 서버, 네트워크, DB 등 인프라를 물리적 설치 없이 빠르게 구축
- 네트워크(VPC), 컴퓨팅(EC2), 저장소(S3, EBS), 보안(IAM, Security Group)
- 비용 관리, 최소 권한, VPC+Public/Private Subnet 구조 필수

---

## 리전/가용영역/서브네팅/라우팅/VPC
- 리전: 데이터센터 분산, 장애/지연 최소화
- 가용영역(AZ): 리전 내 물리적 격리, 장애 대비
- 서브네팅: VPC 내부 논리적 분할, 보안/관리 목적
- 라우팅: 트래픽 경로 지정, Public/Private Subnet 구분
- VPC: AWS 내 가상 네트워크, 보안/자원 통제

---

## 사설 IP/포트포워딩/NAT/포트번호
- 사설 IP: 내부 통신, 외부 통신 시 NAT/Proxy 필요
- 포트포워딩: Bastion Host 등에서 내부 서버 접근
- NAT: 사설 IP를 공인 IP로 변환, Private Subnet 서버의 외부 통신 지원
- 포트번호: 서비스 구분, 보안 그룹/방화벽 관리 필요

# 서버/네트워크 아키텍처

## Web Server vs WAS
- Web Server: 정적 파일 응답, WAS 부하 분산, Nginx/Apache 등
- WAS: 동적 콘텐츠 생성, 내부에서만 동작, Node.js/Spring Boot 등

---

## Reverse Proxy
- DNS: 도메인 → IP 변환
- 포워드 프록시: 내 IP → 외부 IP
- 리버스 프록시: 외부 요청을 내부 서버로 전달

### 구조 예시
- 같은 서버, 다른 포트
```
사용자 → A 서버의 80포트 (Nginx)
           ↓
       리버스 프록시
           ↓
    같은 A 서버의 8080포트 (Node.js)
```
- 다른 서버
```
사용자 → A 서버의 80포트 (Nginx)
           ↓
       리버스 프록시
           ↓
       B 서버의 8080포트 (Spring Boot)
```

### 구체적 예시
```bash
[사용자] → www.naver.com:80
           ↓
     [웹 서버: Nginx]
           ↓
     리버스 프록시로 내부 요청
           ↓
    [WAS: Node.js or Spring (보통 3000, 8080 포트)]
```
