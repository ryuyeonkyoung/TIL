## 문제 1: Offset 페이징이 성능에 좋지 않은 이유는?
- Offset은 앞에 있는 데이터를 **모두 읽고** 건너뛰기 때문에, 페이지가 뒤로 갈수록 읽는 데이터 양이 많아진다.
```sql
LIMIT 15 OFFSET 9999; -- 9999개를 다 읽은 다음 10000번째부터 10015번째까지 보여줌
```

## 문제 2: (INNER) JOIN으로 좋아요 수를 집계할 때 생길 수 있는 문제는?

## 문제 4: 워크북의 book 예시에서, 좋아요 수를 실시간으로 보여주는 서비스임에도 불구하고, book테이블에 likes컬럼을 직접 두지 않고 COUNT로 매번 세는 이유는?
